SA-LIB AI Workshop 2026 · Day 2 · folder 01_langgraph

LangGraph, drawn out

An agent is a loop: think, act, look at the result, repeat. LangGraph writes that loop as a graph you can see, pause, save and resume. This page builds one up from a single node to a research assistant that waits for your approval.

Three parts make every graph

State

The shared whiteboard

A typed dict every node can read. Nodes never edit it directly. They return an update and LangGraph merges it in.

Nodes

Plain Python functions

def node(state) -> dict. A node can call an LLM, run tools, or do ordinary Python.

Edges

Who runs next

Fixed (A → B) or conditional: a function looks at the state and returns the next node's name.

01_first_agent.py

The smallest graph

One node that calls the model. MessagesState is a ready-made state with a single key, messages, that appends new messages instead of replacing the list.

def chatbot(state: MessagesState):
    reply = model.invoke([SYSTEM] + state["messages"])
    return {"messages": [reply]}          # an UPDATE, merged into the state

graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.add_edge(START, "chatbot")
graph.add_edge("chatbot", END)
agent = graph.compile()                        # compile -> a runnable app
agent.invoke({"messages": [{"role": "user", "content": "hi"}]})
02_agent_with_tools.py

The agent loop: two nodes and a conditional edge

This is what LangChain's create_agent builds for you. The agent node asks the model, which can reply with text or with tool calls. tools_condition reads the last message: tool calls send the flow to the tools node, anything else ends the run. After the tools run, the flow goes back to the agent.

model_with_tools = model.bind_tools([web_search, word_count])   # the model now knows the tools exist

graph.add_node("agent", agent_node)
graph.add_node("tools", ToolNode(tools))                  # runs whatever tools were requested
graph.add_edge(START, "agent")
graph.add_conditional_edges("agent", tools_condition)      # -> "tools" or END
graph.add_edge("tools", "agent")                           # the loop
03_agent_with_memory.py

Memory is a checkpointer plus a thread id

Compile with a checkpointer and LangGraph saves the full state after every step. The thread_id in the config picks which saved conversation to continue. The same id gives the same memory, and a new id starts fresh.

agent = graph.compile(checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "chat-1"}}

agent.invoke({"messages": [("user", "hi! my name is m0h.")]}, config)
agent.invoke({"messages": [("user", "what's my name?")]}, config)   # -> "m0h"
agent.get_state(config).values["messages"]                               # inspect what was saved

The same checkpointer makes pause and resume possible. That's the key to the human-in-the-loop step below. InMemorySaver forgets when the script stops. Swap in the SQLite or Postgres saver to keep memory across restarts.

06_langgraph_deep_dive.py

Deep dive: a research assistant that asks before it publishes

A router decides whether a question needs research. Research runs the tool loop. Then the graph pauses and shows you the draft. Approve it and it's published. Reject it with feedback and the researcher tries again with your comment.

  1. A custom state with a reducer

    Several fields instead of just messages. Annotated[list, add_messages] is a reducer: updates to messages are appended, while every other field is simply overwritten.

    class State(TypedDict, total=False):
    question: str
    route: str                                           # "chat" or "research"
    messages: Annotated[list[AnyMessage], add_messages]  # append, don't overwrite
    draft: str
    feedback: str                                        # what the human said

  2. A router with structured output

    The model must answer with one of two words, enforced by a Pydantic schema. The conditional edge then maps that value to a node. We use method="function_calling" because it works on every provider in .env.

    class Route(BaseModel):
    route: Literal["chat", "research"]

def router(state):
    decision = llm.with_structured_output(Route, method="function_calling").invoke(state["question"])
    return {"route": decision.route}

g.add_conditional_edges("router", lambda s: s["route"], {"chat": "chat", "research": "researcher"})

  3. The tool loop inside a larger graph

    Same pattern as step 02, but the exit goes to human_review instead of END. When the model stops calling tools, its reply becomes the draft.

    def after_researcher(state):
    return "tools" if tools_condition(state) == "tools" else "human_review"

g.add_conditional_edges("researcher", after_researcher, ["tools", "human_review"])
g.add_edge("tools", "researcher")

  4. Human-in-the-loop with interrupt()

    interrupt(payload) stops the graph in the middle of the node. The checkpointer saves everything, invoke or stream returns, and your program can show the draft to a person, even hours later.

    def human_review(state):
    decision = interrupt({"draft": state["draft"]})     # <- pauses HERE
    if decision == "yes":
        return Command(goto="publish")
    return Command(goto="researcher", update={"feedback": decision})

g.add_node("human_review", human_review, destinations=("publish", "researcher", "chat"))

    Command does two jobs at once: it updates the state and picks the next node. That's why human_review has no outgoing edges. Its destinations only tell LangGraph where it may jump, so the drawing is correct.

  5. Resume with Command(resume=...)

    To continue, call the graph again with the same thread_id and the human's answer. That answer becomes the return value of interrupt() and the node finishes.

    state = app.get_state(config)
if state.next:                                       # paused? ("human_review",)
    answer = input("approve? ")
    app.invoke(Command(resume=answer), config)

  6. Watch it run with streaming

    stream_mode="updates" yields one item per finished node, which is ideal for showing progress. This is the output for a question that needs research:

    -> router updated: route -> researcher updated: messages, feedback # asks for web_search -> tools updated: messages -> researcher updated: messages, feedback, draft # done researching --- DRAFT for review --- LangGraph 1.2 is the latest release … approve? (yes / or type feedback): yes -> human_review -> publish
05_multi_agent.py

Multi-agent is just more nodes on one state

A researcher, a writer and a reviewer share one TeamState. The reviewer counts words and a conditional edge sends the draft back to the writer while it's too long, up to three drafts. Each "agent" is a node, and a node can be a plain Python step: the reviewer uses no LLM at all.

Cheat sheet

APIwhat it does
StateGraph(State)start a graph whose nodes share State
MessagesStateready-made state: a messages list that appends
add_node(name, fn)register a function as a node
add_edge(a, b)always go from a to b (START / END are special names)
add_conditional_edges(a, fn, map)fn(state) returns the next node's name
ToolNode(tools) · tools_conditionrun requested tools · route to "tools" or END
compile(checkpointer=...)turn on memory, pause/resume and time travel
{"configurable": {"thread_id": …}}which conversation to load and save
interrupt(value)pause inside a node and wait for a human
Command(goto=…, update=…)from a node: update the state and jump
Command(resume=…)from the caller: continue a paused graph
stream(…, stream_mode="updates")yield each node's update as it finishes
get_graph().draw_mermaid()print the graph as Mermaid (paste into mermaid.live)

Common mistakes

  • Returning the whole state from a node. Return only the keys you changed. With a reducer like add_messages, returning the old messages again duplicates them.
  • interrupt() without a checkpointer. There's nowhere to save the paused state, so it raises an error.
  • Resuming with a different thread_id. That starts a new run instead of continuing the paused one.
  • Loops with no exit. Always give a loop a way out (the reviewer stops after 3 drafts). LangGraph's recursion_limit, 25 steps by default, is the safety net.
  • Side effects before interrupt(). On resume the node runs again from its first line, so put emails, payments and other one-off actions after the interrupt.
