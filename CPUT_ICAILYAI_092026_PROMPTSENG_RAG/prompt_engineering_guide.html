Workshop Guide

Prompt Engineering with a Real PDF

This guide uses sample_ocr.pdf, a searchable invoice PDF, to teach beginners how prompts shape model behavior. The simplified code reads the PDF, chunks it, retrieves the most relevant chunk, and sends that chunk plus the question to Groq.

What the code is doing
  1. Read text from sample_ocr.pdf.
  2. Split the text into smaller chunks.
  3. Turn chunks and the question into embeddings.
  4. Choose the most relevant chunk.
  5. Ask Groq to answer using that chunk only.

How Prompting Works Here

Prompt engineering is not magic wording. It is the practice of giving the model a clear task, a clear format, and clear boundaries. In this project, retrieval already narrows the context. Your prompt still matters because it tells the model what kind of answer to produce from that context.

Be specific.
Ask for the exact output you want: summary, table, bullets, risks, or translation.
Set constraints.
Say things like “use bullets,” “quote totals,” or “answer in plain English.”
Name the audience.
Ask for an answer “for a finance officer,” “for a student,” or “for a customs team.”
Ask for structure.
Structured prompts usually produce cleaner teaching examples than vague prompts.

Prompt Examples on the Same File

These all use the same document. What changes is the instruction you give the model. That is the easiest way to teach beginners that prompt design changes the result even when the source file is identical.

Starter

Basic Summary

Use this first to show a simple, broad question.

What are the main findings in this document?
Structured

Executive Summary

Useful for decision-makers who want fast scanning.

Summarize this invoice in 5 bullet points.
Include seller, buyer, total amount, payment terms, and shipping terms.
Extraction

Key Data Fields

Good for teaching information extraction.

Extract the following fields from the document:
- invoice number
- invoice date
- customer name
- total amount
- currency
- country of origin

Return the answer as JSON.
Verification

Consistency Check

Shows how to ask the model to inspect instead of summarize.

Check whether the quantities, unit prices, and line totals are internally consistent.
If you find any mismatch, explain it clearly.
Audience

Explain for a Beginner

Good example of audience-targeted prompting.

Explain this document to a first-year university student who has never seen a proforma invoice before.
Use simple language and short paragraphs.
Operations

Procurement View

Shows how role framing changes the answer.

You are helping a hospital procurement team.
List the ordered items, quantities, prices, and anything they should verify before approval.
Finance

Financial Risk Review

Good for teaching critical prompts instead of descriptive prompts.

Identify the main financial and contractual risks in this invoice.
Focus on payment terms, shipping terms, and any ambiguity in the pricing lines.
Comparison

Arabic vs English Issues

Shows how to ask for discrepancies between representations.

Point out any inconsistencies or possible OCR mistakes in the document text.
Separate confirmed facts from uncertain text.

How to Teach New Users

Step 1.
Start with the basic summary prompt so learners see the default behavior.
Step 2.
Run a structured prompt next so they notice cleaner formatting.
Step 3.
Try a role-based prompt like procurement or finance to show perspective.
Step 4.
End with a verification prompt to show that prompts can inspect, not just summarize.

Teaching takeaway: the file stays the same, the retrieval stays the same, and the model stays the same. The prompt changes the job.
