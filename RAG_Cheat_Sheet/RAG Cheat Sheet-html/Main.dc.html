Cheat sheet

20 RAG Techniques, Explained Simply

Retrieval-Augmented Generation = look things up first, then let the LLM answer using what it found.

STEP 1
Retrieve
Search your documents for the pieces most relevant to the question.
STEP 2
Augment
Paste those pieces into the prompt as context for the model.
STEP 3
Generate
The LLM writes an answer grounded in that context. Every variant below tweaks one of these steps.
Families: Basics Structure Better search Self-checking Agents & loops Research models
01Basics

Standard RAG

The classic recipe. Find the top few similar chunks in a vector database and add them to the prompt.

Query → Retrieve → Generate

Use when: simple Q&A over your docs.

02Basics

Hybrid RAG

Mixes keyword search (exact words, like BM25) with vector search (meaning), then merges both result lists.

Keyword + Vector → Merge → Generate

Use when: names, codes or jargon must match exactly.

03Basics

Contextual RAG

Before indexing, an LLM adds a short note to each chunk saying where it came from and what it is about.

Chunk + Context note → Index

Use when: chunks lose meaning on their own ("it grew 3%").

04Basics

Multi-Source RAG

Pulls from several places at once: databases, PDFs, APIs, the web. Then combines the results.

DB + Docs + Web → Combine

Use when: knowledge is scattered across systems.

05Structure

Hierarchical RAG

Indexes in layers: document summaries, then sections, then chunks. Searches from broad to specific.

Doc → Section → Chunk

Use when: you have huge, well-structured collections.

06Structure

RAPTOR

Groups similar chunks, summarizes each group, and repeats, building a tree. Retrieval can use any level.

Cluster → Summarize → Repeat

Use when: long docs and "big picture" questions.

07Better search

Fusion RAG

Rewrites your question several ways, searches each version, then fuses the rankings (Reciprocal Rank Fusion).

1 query → N queries → Fuse

Use when: questions are vague or many-sided.

08Better search

Multi-Pass RAG

Retrieves in rounds. What it learns in one pass shapes the next search, like following clues.

Search → Learn → Search again

Use when: answers need several hops of facts.

09Better search

Speculative RAG

A small, fast model writes several draft answers from different doc subsets. A big model checks them and picks the best.

Small drafts → Big verifies

Use when: you need speed and accuracy.

10Better search

Auto RAG

Automates the tuning: tries different chunk sizes, embeddings and rerankers, and keeps whatever scores best on tests.

Try configs → Evaluate → Pick

Use when: you don't know which setup works best.

11Self-checking

Corrective RAG

Grades the retrieved docs. If they are weak or wrong, it rewrites the query or falls back to web search.

Retrieve → Grade → Fix → Generate

Use when: your knowledge base is noisy or incomplete.

12Self-checking

Self-RAG

The model decides if it even needs to retrieve, then critiques itself: are the docs relevant, is my answer supported?

Need docs? → Answer → Self-grade

Use when: cutting hallucinations matters most.

13Self-checking

Feedback-Based RAG

Collects user ratings and corrections, and uses them to improve ranking and answers over time.

Answer → User rates → Improve

Use when: a live product that should learn.

14Self-checking

Adversarial RAG

Built to resist poisoned or misleading documents and hidden prompt injections, often tested against attacks.

Retrieve → Filter threats → Generate

Use when: sources are untrusted or security matters.

15Agents & loops

Agentic RAG

An AI agent plans the work: chooses which tools or sources to search, when, and loops until it is satisfied.

Plan → Use tools → Check → Loop

Use when: multi-step, open-ended tasks.

16Agents & loops

ReAct

"Reason + Act." The model alternates between thinking out loud and taking an action (like a search), reading each result.

Thought → Action → Observation

Use when: building tool-using agents.

17Agents & loops

Interactive RAG

Keeps the user in the loop: asks clarifying questions and lets them steer or refine the search mid-conversation.

Ask → Clarify → Refine → Answer

Use when: research or exploratory assistants.

18Research models

REALM

Google (2020). The retriever is trained together with the language model during pre-training, learning what to fetch.

Retriever + LM trained jointly

Why it matters: an early blueprint for RAG.

19Research models

RePLUG

Treats the LLM as a black box. Feeds each doc separately, blends the outputs, and can tune the retriever from LLM feedback.

Doc 1..N → LLM → Ensemble

Use when: you can't modify the model (API-only).

20Research models

ATLAS

Meta. A retriever and a smaller language model trained together, strong on knowledge tasks with only a few examples.

Retriever ⇄ Reader (joint training)

Why it matters: small model, big-model results.
